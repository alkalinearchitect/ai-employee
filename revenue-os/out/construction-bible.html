What NOHUMA is
A managed AI employee, not a chatbot
NOHUMA is a managed AI employee — a persistent Hermes Agent wired into a client's actual stack (email, Slack, CRM, calendar, phone). It runs 24/7, owns a workflow, reports daily, and is built, deployed and supported for the client by the operator.
The model is cloned from Nick Vasilescu's "Dewey": $5,000/month per client, everything included (agents, tokens, usage — no separate line items). T's clone lives at /root/dewey (orchestrator) + /root/client-agents (factory).

Discovery call → agent built → onboarded to Slack/Telegram → live in 48 hours, or the first month is refunded. Day-30: if it hasn't saved >£5k in client hours (measured vs timesheet), the first month is refunded.

Architecture
One brain. Four specialists.
One strong general-purpose orchestrator does 99% of the talking. It hands off to four specialized sub-agents. Isolation minimizes the blast radius — if one breaks, the others keep running.
The four specialists
· Outbound — lead generation & first touch
· Sales follow-up — nurture, chase, book
· Content / assets — proposals, reports, posts
· Support — tickets, tenant/customer comms
For a construction client these map directly: outbound to FM/estates buyers, sales follow-up on tenders, content on PQQs/reports, support on tenant/ticket triage.
T's /root/dewey/AGENTS.md already mirrors this 1+4 structure. The construction bible reuses it wholesale.

Can it handle construction?
Yes. It is built for exactly this.
Construction's problem is not building — it is the administrative tax around building: tendering, compliance, chasing, reporting. Those are document-and-workflow jobs. An AI employee owns document-and-workflow jobs 24/7.
The 206,000-worker gap by 2030 (CITB) cannot be hired away. Automating the non-building work is the only lever left. NHUMA is that lever — per desk, per framework, per region.
Verdict: fully capable of every use case in this bible, drafts-only, on the client's own stack.
The only thing it can't do is swing a hammer. That was never the bottleneck.
